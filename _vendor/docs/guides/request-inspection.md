# Inspect and edit conversion input

Open **Inspect / edit LLM input** in the conversion settings before converting. This is a local preparation step: it does not call an AI, read credentials or store a new conversion.

The left pane shows each clip/shot segment, clip-local timing, original source interval, the action/visual context and assigned dialogue. A split source shot still carries its whole source action list; those actions do not have individual source timestamps. The application cannot infer exactly which action happens at which second. Use the segment-direction field to specify what should happen now and what must wait. The compiler explicitly distinguishes whole-shot context from segment-specific direction, but this does not prove that a video model will follow it.

Advanced fields expose the actual application system prompt, user request JSON, fixed output schema and provider system text including the schema suffix. API keys, authentication headers, image pixels and private connection settings are excluded. Provider adapters also transmit the same schema through their selected structured-output mechanism where applicable; this inspector is not a raw authenticated HTTP dump.

You can edit the system prompt, story-context prose in `brief`, and a segment's `segment_instruction`, `source.visual`, `source.actions`, `source.purpose`, `source.continuity` and camera descriptions. Descriptive source edits apply only to that conversion segment and are marked `user_edited_segment`. Source storyboard documents remain unchanged. Clip/shot IDs and order, timings, assigned original dialogue/speakers, states and reference bindings remain protected. Change those in the source editor or split settings instead. The application always adds its identity/action-scope contract, and all output validation still runs.

**Validate and apply edits** validates locally and clears the conversion consent checkbox. The normal conversion button sends the reviewed input after you consent again. If the source, model, guide, references, selection or split plan changes, the backend rejects the stale edit before any AI call. Use **Reload original request** to start from the new settings. Closing without applying does not activate new edits. Applied edits are in page memory and do not survive a refresh or changing the loaded storyboard.

New successful conversions store the initial logical request, each actual bounded repair request, their parsed JSON outputs and the final validated direction object. Open **View LLM requests / output** in the result's generation metadata to compare or download them. Older conversions have no retroactive request trace. Failed conversions are not saved; the input inspector remains available, but failed response bodies are not persisted as a new result. Keep downloaded traces private if your story or personas are private.

If a future action appears in the wrong shot, compare the segment input with the corresponding raw `request_trace[*].output` and final direction object. This distinguishes action context supplied by the split plan from a change introduced by the LLM. The generated video's interpretation is a separate stage.
