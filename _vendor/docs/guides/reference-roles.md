# Reference selections

The user selects character, background, prop or other and the part of the image to use. Descriptions are optional except for other, whose intended purpose is required. Each manifest entry includes English guidance for its role; this is an application default, not an observation of the image. Never claim to have inspected an attachment.

Reference kinds are character, background, prop and other. Prop references define the appearance of a named object, not an extra character or a speaker. Use reference_targets to bind all images of the same target to one object. An associated character is an identity hint, not an instruction to put that object in their hands in every shot. The source start/end states, action prerequisites, transfers and current holder remain authoritative. Do not introduce a referenced prop when absent from the approved action. Other references apply only to the user's explicit purpose (for example lighting, palette or style); their usage note is required, and unrelated people/objects/actions must not be copied.

Each speech-independent reference_notes item contains label, note and target_name. Translate target_name into English for prop/other targets; use an empty string for character/background targets. Multiple images of the same target must use the same English target name. Translate notes verbatim in intent; never claim visual analysis. Source target names and IDs in reference_targets are lookup data, not final prompt text. Keep any internal source labels out of rendered instructions.

shot_ids=[] means all relevant approved shots; a nonempty list restricts a whole target and all its images to those exact source shots. At conversion, map that restriction to the current clip's local shots. A reference excluded from this clip must not affect its context, subject definitions, camera, style or action. Preserve the global attachment order even for unused pictures. Never insert new objects, actions, dialogue, transfers or camera changes just to use an attachment. This application supports these multi-image references in H3/Seedance reference modes; LTX's existing starting-frame mode does not accept this reference bundle.

appearance is the basic character reference: face, hairstyle, clothing, colors and accessories. face is face and hairstyle only. body is proportions and silhouette, outfit is clothing/accessories, expression is acting reference, and detail uses the user's specific note. environment is location layout, never an extra person.

Multiple images for one character are views or feature references for that same person. Do not turn them into additional characters. Component-specific images refine that component rather than blending every face or outfit together. Explicit reference notes refine or limit the default role; preserve them. Keep the approved storyboard's actions, camera and story intent.

A blank note is valid for ordinary appearance, face, body, outfit, expression and environment selections. Use the role's default guidance without asking the user to invent visual attributes. An unprovided detail is unknown; do not fabricate it. Keep attachment order and labels exact for the target model.
